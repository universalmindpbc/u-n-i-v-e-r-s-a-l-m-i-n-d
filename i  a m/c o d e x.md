# CODEX.md

## About Ben

Ben is an Executive Creative Director.

He works visually, not programmatically.

He designs in Keynote and treats those mockups as the creative source of truth.

His design files should be reproduced faithfully rather than creatively reinterpreted.

---

# Communication

Use plain English.

Avoid software engineering jargon where a simpler explanation exists.

When explaining technical concepts, assume Ben is interested in the outcome rather than the implementation.

---

# Design Collaboration

Ben provides exact design direction.

Do not redesign layouts unless requested.

Do not "improve" typography, spacing or composition without approval.

Suggestions are welcome, but should always be presented as optional alternatives.

Whenever possible:

Show Version A (approved)

Show Version B (suggestion)

Allow Ben to choose visually.

---

# Creative Process

Ben thinks like a film director.

The priority is:

composition

typography

motion

atmosphere

emotion

User interface decisions should support those priorities.

---

# Development Workflow

Projects are built locally on Ben's Mac.

The final deliverable should be a finished website folder ready for upload to Panthur cPanel hosting.

Avoid solutions that require ongoing server administration unless specifically requested.

---

# Development Style

Build incrementally.

Complete one visual milestone before beginning the next.

Avoid building unnecessary features ahead of schedule.

Prefer simple, maintainable solutions.

---

# Visual Accuracy

Treat screenshots and Keynote mockups as the source of truth.

Aim for pixel-level fidelity wherever practical.

If implementation differs noticeably from the supplied artwork, ask before changing the design.

---

# AI Behaviour

Suggest ideas.

Do not impose ideas.

Prototype ideas rather than debating them.

Visual comparisons are preferred over lengthy discussion.

The Creative Director makes the final decision.

---

# Code Style

Write clean, readable code.

Keep project structure organised.

Comment only where it adds useful context.

Avoid unnecessary complexity.

Optimise only after the approved design has been faithfully implemented.

---

# Responsive Design

Desktop and laptop are the primary targets.

Responsive behaviour should preserve the original composition wherever practical.

If a mobile-specific layout becomes necessary, keep the visual language consistent with the desktop experience.

---

# Long-Term Goal

Every project should feel carefully directed rather than generated.

The objective is craftsmanship.

Not automation.
